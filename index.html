Core Concept

What is CyberOsint?

CyberOsint is a cybersecurity intelligence platform that continuously collects data from multiple sources, organizes and normalizes it, and provides powerful tools to search, correlate, and investigate threat intelligence in a single interface.

01 // INGRESS
Sources
Government CERTs, vulnerability registries, advisories, research blogs, and threat telemetry.
02 // COLLECT
Connectors
Scheduled, rate-limited, and SSRF-protected autonomous collectors polling feeds.
03 // PROCESS
Normalize
Converts raw JSON, XML, and Atom payloads into uniform CyberOSINT schemas and deduplicates via SHA-256.
04 // ENRICH
Classify
Categorizes content into CVE, Advisory, Threat Intel, or Research, evaluating CVSS metrics.
05 // GRAPH
Connect
Extracts named entities (Vendors, Products, Malware, CVEs) and maps relational graph links.
06 // RETRIEVAL
Search
Simultaneously executes full-text BM25 and dense vector search, fused by Reciprocal Rank Fusion (k=60).
07 // ANALYSIS
Investigate
Analysts explore dossiers, view timelines, filter KEV exploits, and query cross-referenced intelligence.
The Problem

Why Was CyberOsint Created?

Cybersecurity information is scattered across dozens of disconnected silos, making timely threat detection and correlation difficult for security teams.

Fragmented Information Silos

Security teams waste valuable time manually checking CISA alerts, vendor portals, GitHub advisories, and security blogs one by one without a single unified view.

Alert Fatigue & Duplicates

The same breaking vulnerability is reported across multiple news outlets and advisories with varying titles, cluttering threat feeds with duplicate noise.

Disconnected Relationships

A CVE alone does not tell the full story. Understanding which vendor, products, threat actors, and active ransomware campaigns are linked requires relational entity mapping.

Keyword Search Blindspots

Traditional search engines miss critical intelligence when queries use synonyms (e.g., searching for "credential theft" misses reports using "infostealer dump" without vector search).

Search Technology

Hybrid Search Explained Simply

Why choose between keyword search and AI vector search when you can fuse both? CyberOsint uses Reciprocal Rank Fusion (RRF) to deliver balanced, highly relevant results.

1. Text Search (BM25)

Finds exact keyword matches, specific CVE identifiers (e.g. CVE-2024-38812), product names, and specific error codes with high lexical precision.

2. Vector Search (384-D)

Understands concepts and semantic meaning. Searching for "credential dump" will return records about "infostealers" and "stealing passwords" even without matching words.

3. RRF Rank Fusion (k=60)

Takes the rank order from both searches and calculates a unified score. The highest-ranked items in both methods float directly to the top without score scale bias.

Getting Started

Run CyberOsint Locally

Clear, reproducible setup instructions for running the complete sovereign platform on your workstation.

BASH // LOCAL SETUP & RUN 
# 1. Clone the repository
git clone https://github.com/Suraj541/CyberOsint.git
cd CyberOsint

# 2. Configure environment template
cp .env.example .env

# 3. Setup Python virtual environment & backend
python -m venv .venv
# Windows: .venv\Scripts\activate | Linux: source .venv/bin/activate
pip install -r apps/api/requirements.txt

# 4. Start the FastAPI backend server (Port 8000)
uvicorn app.main:app --app-dir apps/api --host 127.0.0.1 --port 8000 --reload

# 5. In a second terminal, start the Next.js 14 frontend (Port 3000)
cd apps/web
npm install
npm run dev

# Dashboard: http://localhost:3000 | API Docs: http://127.0.0.1:8000/docs
DOCKER // COMPOSE STACK 
# 1. Clone repository & copy environment configuration
git clone https://github.com/Suraj541/CyberOsint.git
cd CyberOsint
cp .env.example .env

# 2. Launch complete stack (PostgreSQL, Redis, OpenSearch, API, Web)
docker compose up -d

# 3. Check service health status
docker compose ps

# 4. View live ingestion logs
docker compose logs -f api
BASH // TEST SUITES 
# 1. Run all backend pytest suites
pytest tests/ -v

# 2. Run hybrid RRF search unit verification
pytest apps/api/tests/test_rrf_comprehensive.py -v

# 3. Verify frontend TypeScript types and production build
cd apps/web
npx tsc --noEmit
npm run build
